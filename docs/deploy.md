# Deploying MATCHBACK (Neon + Render + Vercel)

Whoever deploys uses **their own** Neon, Render and Vercel accounts. Secrets live only in those dashboards. **Never commit them or paste them in group chat** — this repo is public.

```
Browser ─▶ Vercel (web/)  ──API_URL──▶  Render (api/, render.yaml)  ──DATABASE_URL──▶  Neon Postgres
```

Order: **1 Neon → 2 Render → 3 Vercel → 4 connect the URLs → 5 seed → 6 check**. Always deploy from `main`.

## 0. GitHub access (collaborators)

The repo belongs to `wipabhorn-s`. Render and Vercel deploy automatically on every merge to `main` through their **GitHub App**. A collaborator can't install an app on someone else's personal repo, so:

- When Render/Vercel asks for access, **request** the install for `matchback`. The repo owner gets a GitHub notification and approves it, choosing **Only select repositories → matchback**.
- No time to wait? On Render, use **Public Git repository** with the repo URL. You then press **Manual Deploy** after each merge yourself.

## 1. Neon (database)

1. Create a project: name `matchback`, region **AWS Asia Pacific 1 (Singapore)**, Postgres 17.
2. **Connect**, then copy the connection string with **Connection pooling turned off** (the *direct* URL, host without `-pooler`). Prisma migrations don't work through the pooler.
3. Make sure it ends with `?sslmode=require`. This is your `DATABASE_URL`.

## 2. Render (API)

1. **New → Blueprint**, pick the `matchback` repo, branch `main`. Render reads [`render.yaml`](../render.yaml).
2. It asks for the `sync: false` values:

| Key | Value |
|---|---|
| `DATABASE_URL` | the direct Neon URL from step 1 |
| `FRONTEND_URL` | `https://example.com` for now (fixed in step 4) |
| `BREVO_API_KEY`, `MAIL_FROM` | **required**: production refuses to boot without them. Get a free key at brevo.com → SMTP & API → API Keys. `MAIL_FROM` must be a sender you verified in Brevo. |
| `GEMINI_API_KEY` | optional server-side key (without it or when Gemini fails, the AI buttons use deterministic fallback) |
| `GOOGLE_CLIENT_ID` | optional (leave empty) |

`ACCESS_TOKEN_SECRET` and `INTERNAL_API_SECRET` are generated by Render automatically.

3. **Apply** and wait for the deploy. The build runs `pnpm install --prod=false && pnpm build`, and the start runs `prisma migrate deploy` before the API.
4. Open `https://<your-service>.onrender.com/health` and you should get `{"status":"ok"}`.

**No Brevo account yet?** As a temporary workaround only, set `NODE_ENV=development` on the service: emails then go to the Render logs instead of being sent. Switch back to `production` once Brevo is set up.

## 3. Vercel (web)

1. **Add New → Project**, import `matchback`, and set **Root Directory = `web`** (framework is detected as Next.js).
2. **Settings → Node.js Version: 24.x.**
3. Environment Variables (Production):

| Key | Value |
|---|---|
| `API_URL` | `https://<your-service>.onrender.com` (no trailing `/`) |
| `AUTH_SECRET` | random: `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"` |
| `AUTH_URL` | your Vercel URL, e.g. `https://matchback.vercel.app`. **Required**: without it login silently bounces back to `/login`. |
| `INTERNAL_API_SECRET` | copy the value Render generated (Render → service → Environment) |
| `ENABLE_EXPERIMENTAL_COREPACK` | `1`, so Vercel uses pnpm 11.8.0 from `packageManager`. Older pnpm fails our `engines` check. |

4. Deploy. If it fails at install with an engine error, check the Node version (24.x) and the corepack variable.

## 4. Connect the URLs

On Render, set `FRONTEND_URL` = your Vercel URL (no trailing `/`), then **Save**. Render redeploys.

## 5. Seed the demo data (once, and again whenever you want to reset the demo)

Render's free plan has no shell, so run the seed from a laptop against Neon. This uses **separate demo passwords** for production, not the ones in your local `.env`.

PowerShell, inside `matchback/api` (needs Node 24.15+ and `pnpm install` done):

```powershell
$env:DATABASE_URL = "<direct Neon URL>"
$env:SEED_DEMO_PASSWORD = "<new demo candidate password>"
$env:SEED_ADMIN_PASSWORD = "<new admin password>"
pnpm prisma migrate deploy
pnpm db:seed
```

Then close that terminal so the URL and passwords don't stay in your session. Passwords must have 8+ characters with upper, lower, a number and a symbol. Share them with the team privately, not in the repo.

## 6. Check like a judge would

In a **private/incognito window**:
- [ ] `<render>/health` returns `{"status":"ok"}`
- [ ] The Vercel home page shows sample jobs (proves web → API → DB)
- [ ] Log in as `demo@matchback.dev`; Discover shows cards; a swipe works; a job detail page loads
- [ ] No errors in Render logs / Vercel function logs

**Free-tier note:** Render's free API sleeps after ~15 min idle, and the first request can take ~50 s (`apiFetch` retries for up to 60 s). Open the site yourself a few minutes before judging.

## Updating

Merge to `main` → Render and Vercel redeploy automatically (or press Manual Deploy). Migrations apply on Render start. New demo data needs step 5 again.
